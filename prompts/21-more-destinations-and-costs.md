# Prompt 21 — More destinations and cost estimates

Production serves 30 destinations in 23 countries (`content/initial-v8.json`). Whole regions have none or few: the Middle East, South Asia, sub-Saharan Africa, the UK, Portugal, and the Nordic countries (owner, 2026-11-08). Only 10 destinations have a cost estimate. This phase adds destinations with coordinates (Phase 20, ADR-036), fills more cost estimates and best months under the Phase 8 and Phase 9 source rules, and measures the effect with `npm run quiz:simulate`. The first response is investigation and a proposal only: no content file, code, configuration, or database change.

**One import for Phases 20 and 21** (owner, 2026-11-08): the owner wants as few production imports as possible. `content/initial-v9.json` (Phase 20 coordinates) is not imported on its own. The Phase 20 code still ships first (migration `0003`, then the push to `main`), because the deployed admin API must know `location` before any bundle with locations is imported; an older admin API would drop the field without an error. This phase's `content/initial-v10.json` is `initial-v9.json` plus the approved additions, and it is the one bundle imported. The Phase 20 production check (map and map links) is done after that import.

Do not run remote Cloudflare commands, deploy, import content, change quiz settings, push, commit, or add, remove, or update dependencies without the owner's explicit approval for that action. Dashboard and admin-console steps on production are the owner's; describe them, do not perform them. A push to `main` deploys production. The account must stay on Workers Free. AI stays disabled.

If this phase is still open in the first week of December 2026, remind the owner of the dated Workers Logs and Billing check ([OPERATIONS.md](../docs/en/OPERATIONS.md) section 3 "Dated").

## Tasks
1. **Coverage and gap review (local, no content change).** From `initial-v9.json` and `npm run quiz:simulate`: destinations per region, type, and attribute profile; top-result shares and destinations that rarely reach the top results; and, per destination, which of costs, best months, and recommended days are empty, with the rule that excluded each value before (Phases 8, 9, 13, 16).
2. **Destination proposal (owner review).** Propose new city/region-level destinations (ADR-007, no Japan) in the regions above and any other gap from task 1, to a total the owner approves, with a recommendation (for example 10 to 12 new ones, about 40 in all). For each: slug, country (new countries with names in `ja`, `en`, `es`, and `fr`), type, region, the gap it fills, its representative point with the basis (DATA_MODEL.md "Phase 20 schema notes"), and anything hard to describe without live facts. Avoid destinations whose main appeal depends on current safety, visa, or access conditions; say why when a region is left without one.
3. **Content for each approved destination (owner review).** As in Prompt 13 task 3, with `fr` added (ADR-032): scores for all 11 attributes with a one-line reason each (editorial judgements, labelled so); name, summary, highlights, and general cautions in natural `ja`, `en`, `es`, and `fr`; recommended days; and the coordinates, checked with `node scripts/build-world-map.mjs <land> --check <countries> content/initial-v10.json` (the Natural Earth files are downloaded again only with the owner's approval).
4. **Costs and best months (owner review).** For new and existing destinations, add estimates and best months only under the approved rules (Phase 8 and Phase 9 rules, and the Phase 16 rule for converted `USD`/`EUR`/`JPY` estimates), with every source read and linked in the review copy. Leave a value empty when no source meets the rules; never estimate one. Propose any new rule for the owner's decision before adding values under it.
5. **Bundle and checks (after approval of tasks 2–4).** Write `content/initial-v10.json` = `initial-v9.json` plus the approved countries, destinations, and values, with nothing else changed; extend `test/node/content-bundle.test.ts` to check that. Every destination has a location. Run the simulation, record the comparison with `initial-v9.json` in a "Phase 21 verification log", and propose any quiz-setting change (the owner makes it in the admin console). Provide a rendered review copy of all new texts in four locales with every source linked. Rehearse the import locally in update mode. Run `npm run check` and `npm run test:e2e`.
6. **Release (owner steps).** If Phase 20 is not deployed yet: the migration session and the pushes of [the Phase 20 release steps](../docs/working/DECISIONS.md) ("Phase 20 verification log"), without importing `initial-v9.json`. Then push the Phase 21 commit and import `initial-v10.json` once in update mode: existing destinations change only by `location` and the approved values, and the new countries and destinations are created. Check production without login in four locales at phone and desktop width: `/api/diagnosis-content` matches the bundle, the map shows pins for all results, the map links work, and quizzes with `JPY`, `USD`, and `EUR` budgets show the new estimates.
7. **Documentation.** ADR-028 content files, counts in README (with the Japanese twin) and any stable doc, IMPLEMENTATION_PLAN.md, and the Phase 20 verification log (the deferred production check and the owner's coordinate approval of 2026-11-08).

Not part of this phase: new attributes or questions, score changes to existing destinations unless the owner approves a listed proposal, images, production AI, and a dated exchange-rate table.
