# Prompt 20 — Destination map

The results list says which country each destination is in, but not where it is. The owner wants a map, and only if it is guaranteed free (2026-11-08). This phase adds coordinates to destinations, a world map drawn and served by the app itself with a pin for each shown result, and a link from each card to an external map. The next phase adds destinations and cost estimates, and its new destinations get coordinates from the start.

Why a self-hosted map: requests to Workers static assets are free and unlimited ("Requests to static assets are free and unlimited", Cloudflare Workers static assets billing page, read 2026-11-08), and Natural Earth data is public domain without attribution. No tile server, map API, or API key is used: the OpenStreetMap tile policy gives no availability guarantee and may block use without notice, and Google Maps APIs need a billing account.

Ranking, fit, and strengths do not change. No new runtime dependency, no external request from the page, and no CSP change. AI stays disabled. This phase has a schema change: the owner applies the migration to the production database before the code reaches `main` ([DEPLOYMENT.md](../docs/en/DEPLOYMENT.md) section 4). Do not push, commit, deploy, or download files without the owner's explicit approval; a push to `main` deploys production.

## Tasks
1. **Coordinates (schema and content).** Add nullable `latitude` and `longitude` (degrees, WGS 84) to `destinations` with a Drizzle migration that is backward compatible with the deployed code. Carry them through the content bundle, the import diff, admin validation (both or neither; latitude −90..90, longitude −180..180), the admin destination form, and `/api/diagnosis-content`. A destination without coordinates is valid and shows no pin. Define the representative point in DATA_MODEL.md: the city centre for a city; for a region or island, a point inside it that a traveller would recognize (for example its main town), rounded to two decimals.
2. **Coordinates for the 30 destinations.** Build `content/initial-v9.json` from `initial-v8.json` with coordinates only. List each point with its basis (the place it marks) for the owner to review before the import. Check every point falls on land in the map data, inside its country.
3. **World map asset.** Write a script under `scripts/` that turns Natural Earth 1:110m land or countries data into one simplified SVG in `public/`, with the Equal Earth projection implemented in a small shared module (no new dependency). Commit the generated SVG and the script, not the raw Natural Earth files; ask the owner before downloading them (file name, source URL, size). Target at most about 100 KB. The SVG has no text and reads on light and dark backgrounds through the page's colors.
4. **Map on the results page.** One map for the shown results, with numbered pins that match the card ranks, placed with the same projection module. It supplements the list: the list stays the primary content, the map has a text alternative naming the shown destinations and their countries, pins are not the only way to reach a result, and nothing depends on hover. Results without coordinates are left off the map with no error. Lazy-load the map so the quiz pages do not fetch it. It must fit 375 px without horizontal scroll. Localize every label in all four locales.
5. **External map link.** On each card with coordinates, add a link that opens the point in an external map in a new tab, with the same new-tab hint as the search buttons. Use Google Maps URLs (`https://www.google.com/maps/search/?api=1&query=<lat>,<lng>`; documented, no key) unless the owner picks OpenStreetMap (`https://www.openstreetmap.org/?mlat=<lat>&mlon=<lng>#map=8/<lat>/<lng>`) at the start of the phase. The link carries only the coordinates, never answers or constraints.
6. **Tests and checks.** Unit tests for the projection (known points, edges, the round trip of pin placement), coordinate validation (both or neither, ranges), the import diff, and the content API. Component tests for the map (pins and numbers, text alternative, results without coordinates) and the map link. E2E: the results page shows the map, the map asset is a real same-origin SVG with `nosniff` and not the SPA's HTML, the quiz pages do not request it, and no request leaves the origin. Run `npm run check` and `npm run test:e2e`. In the built-in browser, check results in all four locales at 375 px and desktop width, in light and dark color schemes.
7. **Release (owner steps).** Write the owner session for the migration: Time Travel bookmark, apply to `travel-discovery-production`, verify the columns, log out. Then the owner pushes `dev`, waits for CI, pushes `main`, and imports `initial-v9.json` through the admin console. The deployed code must work before the import (no coordinates yet: no map, no link). After each step, check production without login.
8. **Documentation.** DATA_MODEL.md (columns and the representative-point rule), SPEC.md (the map and the map link), and ARCHITECTURE.md if the asset flow needs it, each with its Japanese twin in the same commit. ADR-036 (self-hosted static map, why not tiles or a map API, projection, size) and a "Phase 20 verification log" in `docs/working/DECISIONS.md`. Update IMPLEMENTATION_PLAN.md, the README status with its Japanese twin, and the content notes in OPERATIONS.md if the import steps change.

Not part of this phase: new destinations and cost estimates (Phase 21); zoomable or tiled maps; a map on any page other than results; destination images; shareable result URLs; and production AI.

## Acceptance
- Destinations have optional, validated coordinates through schema, bundle, import, admin, and the content API; the migration is backward compatible.
- `content/initial-v9.json` differs from `initial-v8.json` only by coordinates, which the owner reviewed.
- The results page shows a self-hosted world map with numbered pins and a text alternative in all four locales, and each card with coordinates links to an external map in a new tab.
- The page makes no new external request, the CSP is unchanged, and the quiz pages do not load the map.
- `npm run check` and `npm run test:e2e` pass, AI is disabled, and the account stays on Workers Free.
- After the owner's migration, push, and import, production shows the map and links, checked without login.
