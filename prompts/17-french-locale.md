# Prompt 17 — French locale

The public UI, the admin UI, and all content are localized in `ja`, `en`, and `es` (ADR-012). This phase adds French (`fr`) with the same features, fallbacks, formatting, and tests, following the shared `add-ui-locale` task prompt and the plan the owner approved on 2026-10-31 (ADR-032). It runs before Phase 16, so the French bundle is `content/initial-v7.json` and Phase 16 builds `initial-v8.json`.

Do not run remote Cloudflare commands, apply migrations to preview or production, deploy, import content, push, commit, or add, remove, or update dependencies without the owner's explicit approval for that action. Dashboard and admin-console steps on deployed environments are the owner's; describe them, do not perform them. The account must stay on Workers Free. AI stays disabled in every environment.

## Read first
`CLAUDE.md`, [SPEC.md](../docs/en/SPEC.md) (localization), [ARCHITECTURE.md](../docs/en/ARCHITECTURE.md) (localization), [DATA_MODEL.md](../docs/en/DATA_MODEL.md), `docs/working/DECISIONS.md` (ADR-012, ADR-020, ADR-021 "Migration safety", ADR-022, ADR-028 including "Update mode", ADR-032), [OPERATIONS.md](../docs/en/OPERATIONS.md) section 8 (imports and Time Travel bookmarks), `shared/locales.ts`, `src/i18n/`, `admin/src/i18n/`, `admin/src/import/`, `server/admin/validation.ts`, `server/ai/prompt.ts`, and `content/initial-v6.json`.

## Tasks
1. **Infrastructure.** Add `fr` to `SUPPORTED_LOCALES` with the fallback `fr → en → ja`. Replace hard-coded locale lists (`server/admin/validation.ts`, the admin translation fields and import diff, `scripts/check-deployment.mjs`) with lists derived from `shared/locales.ts` where the code allows it. Language detection maps `fr-*` to `fr`; `<html lang>`, titles, and `Intl` formatting follow the active locale as for the other locales. Add `fr: "French"` to the AI prompt's language names; the output checks need no change for a Latin-script locale.
2. **Migration.** Generate `migrations/0002_*` with drizzle-kit so the seven `*_translations` tables accept `fr` in their `locale` CHECK constraint. SQLite cannot alter a CHECK constraint, so the tables are rebuilt; the migration must preserve every row and foreign key (as the `destinations` rebuild in ADR-021 did). Test it on a local database that holds the seeded content. Applying it to preview and production is an owner-approved step, after a Time Travel bookmark.
3. **UI strings.** Add `src/i18n/messages/fr.ts` and `admin/src/i18n/messages/fr.ts`, typed with `Messages`, and register them. Write natural French in the product's tone (the `vous` form), not a word-for-word copy of the English; compare with `ja` and `es` where tone matters. Follow French punctuation (narrow no-break space before `:`, `?`, `!`, `;`), and add `fr: "Français"` to every `language.names`.
4. **Import update mode.** Extend the update mode (ADR-028) from destinations to existing countries, attributes, categories, and questions, through the existing `PUT` endpoints: compare in one shape, show the changed fields, re-read before each update, and stop on a changed `updatedAt`, as for destinations. A question update must not archive options: block the update if the file lacks an option the database has. Still no new endpoint or server code.
5. **Content.** Create `content/initial-v7.json`: `initial-v6.json` plus `fr` translations of every country, attribute, category, destination (name, summary, highlights, cautions, best-season text, image alt), question, option, and cost basis, with nothing else changed (check by comparing the parsed files without `fr`). Translate from `en` and `ja`; add no facts; keep source names, URLs, numbers, and dates unchanged. The project has no draft marker, so provide a rendered review copy of all `fr` text beside `en` for the owner before the commit. Add `fr` rows to `db/seed/dev.sql`.
6. **Tests and checks.** Extend the locale-parameterized tests to `fr`: message completeness, fallback chain, language detection, `lang` metadata, axe on every public page state, the diagnosis flow, the public and diagnosis-content APIs, the seed check, the content bundle test (all four locales required), admin localized content, the import diff and planning for the new item types, AI prompt and output checks, and the E2E language switch. Run `npm run check` and `npm run test:e2e`. In the built-in browser, check home, trip details, quiz, results, and 404 in `fr`, and the admin pages, at 375 px and desktop width: no missing keys, no overflow, correct number, date, and currency formats, and switching between all four locales both ways.
7. **Rollout (owner steps, each approved).** On preview, then production: Time Travel bookmark, apply migration `0002`, deploy the public and admin Workers, then import `initial-v7.json` with the update mode and record a bookmark after it ([OPERATIONS.md](../docs/en/OPERATIONS.md) section 8). Check that `/api/diagnosis-content` matches the bundle in all four locales, run `scripts/check-deployment.mjs`, and answer a complete quiz in `fr`. Record versions, bookmarks, and results in a new "Phase 17 verification log" in `docs/working/DECISIONS.md`.
8. **Documentation.** Add `fr` to `CLAUDE.md` and to every stable doc that lists locales (SPEC, ARCHITECTURE, DATA_MODEL, DEVELOPMENT, OPERATIONS, DEPLOYMENT, AI_ENABLEMENT, and the root README), each with its Japanese twin in the same commit. Record the new bundle in ADR-028 "Content files" and the outcome in ADR-032.

Deferred, not part of this phase: other locales; a `docs/fr/` translation; evaluating AI output in French (an `fr` review joins the AI enablement steps); new or changed content other than `fr` text; and Phase 16's cost and season work.

## Acceptance
- The owner approved the migration before it ran on preview or production, and a local test shows it preserves every row.
- UI strings are complete in `fr`, and missing `fr` content falls back `fr → en → ja` with the "shown in <language>" hint.
- `content/initial-v7.json` differs from `initial-v6.json` only by `fr` translations, and the owner approved the rendered review copy.
- The main public and admin pages work in `fr` at 375 px and desktop width, and switching between all four locales works.
- After the approved rollout, `/api/diagnosis-content` matches the bundle in all four locales on preview and production, and complete quizzes pass in `fr`.
- `npm run check` and `npm run test:e2e` pass, AI is disabled in every environment, and the account stays on Workers Free.
