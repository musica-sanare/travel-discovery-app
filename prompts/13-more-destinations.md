# Prompt 13 — More destinations

Production has 18 published destinations in 15 countries (`content/initial-v5.json`): 5 in Asia, 7 in Europe, 2 in Hawaii and Australia, and 4 in South America, scored on 11 attributes and asked about with 29 questions. Whole regions are missing, and in the Phase 12 simulation a few destinations take most of the top results while others rarely appear. This phase adds destinations so that results cover more travel styles and regions, and measures the effect with `npm run quiz:simulate`. The AI notices and limits in the UI (Phase 14) are a later phase. The first response is investigation and a proposal only: no content file, code, configuration, or database change, and no deployment.

Do not run remote Cloudflare commands, deploy, import content, change quiz settings, push, commit, or add, remove, or update dependencies without the owner's explicit approval for that action. Dashboard and admin-console steps on deployed environments are the owner's; describe them, do not perform them. The account must stay on Workers Free: the only accepted charge is the owner's existing domain registration. AI stays disabled in every environment.

If this phase is still open in the first week of December 2026, remind the owner of the dated Workers Logs and Billing check ([OPERATIONS.md](../docs/en/OPERATIONS.md) section 3 "Dated").

## Tasks
1. **Coverage review (local, no content change).** From `initial-v5.json` and `npm run quiz:simulate`, report the current spread: destinations per region, type (`city`, `region`, `island`), and score profile on each of the 11 attributes, and which profiles have few or no destinations (for example warm and easy to get around but quiet, or cool climate with strong nature). Use the simulation's top-result shares to show which destinations dominate or rarely appear.
2. **Destination proposal (owner review).** Propose new city/region-level destinations (ADR-007) to reach a total the owner approves, with a recommendation (for example about 30). Do not propose Japan, because the app recommends overseas destinations and Japanese is the default locale. For each candidate give: slug, country (new countries with names in `ja`, `en`, and `es`), type, region, the gap it fills from task 1, and anything that makes it hard to describe without live facts. Prefer destinations a traveller can name and an editor can describe from general knowledge, and avoid ones whose main appeal depends on current safety, visa, or access conditions.
3. **Content for each approved destination (owner review).**
   - Scores for all 11 attributes with a one-line reason each. Scores are editorial judgements (as in ADR-028 `initial-v1.json`), not sourced facts; say so in the review copy. Score with the rubrics of the existing attributes and the Phase 12 rubrics for the four new ones, so new and existing scores are comparable.
   - Name, summary, highlights, and cautions (images remain deferred unless the owner decides otherwise) in natural `ja` (polite style of the UI), `en`, and `es`, curated and not machine-translated at runtime. Cautions stay general (for example altitude, heat, or long travel times) and never state current safety, visa, health, or entry rules.
   - Recommended days as an editorial range.
   - Costs, best months, and best-season text only under the "Phase 8 verification log" and "Phase 9 verification log" rules, with every source read and linked in the review copy; leave them empty where no source meets the rules, and never estimate a missing value.
4. **Existing content.** Existing destinations, attributes, and questions stay unchanged unless the owner decides otherwise. If task 1 shows that an existing score is clearly inconsistent with the rubric (for example a reason Rome or Seoul rarely reach the top 5 in the Phase 12 simulation), list it as a separate proposal with the expected effect on the simulation; changing it uses the update mode and replaces the whole destination (ADR-028).
5. **Bundle and checks (after approval of tasks 2–4).** Write `content/initial-v6.json` = `initial-v5.json` plus the approved countries and destinations (and any approved score changes), with nothing else changed (check by comparing both files without the new items). Extend `test/node/content-bundle.test.ts` only where needed. Run the simulation on `initial-v6.json`, record the comparison with `initial-v5.json` in a new "Phase 13 verification log" in `docs/working/DECISIONS.md` (top-result shares, destinations that never reach the top `resultCount`, distinct question sets), and propose whether the quiz settings should change; quiz settings are changed only by the owner in the admin console. Provide a rendered review copy of all new texts in the three locales with every source linked.
6. **Import (owner steps, each approved).** Preview first: record Time Travel bookmarks before and after, run the import with the update mode (new countries and destinations created, existing items skipped or unchanged), and, before reading the bookmark after the import, confirm through `/api/diagnosis-content` that the new destinations are served; if they are not, record what the Import page showed (the first Phase 12 preview import did not reach the database for an unknown reason). Then check `/api/diagnosis-content` in `ja`, `en`, and `es` against the bundle, run `scripts/check-deployment.mjs`, and answer complete quizzes in all three locales in the built-in browser. Then the same on production. Record bookmarks, counts, and results in the "Phase 13 verification log".
7. **Documentation.** Update ADR-028 (content files) for `initial-v6.json`, any stable doc whose content or counts change, and the Japanese twins of any changed stable doc.

Deferred, not part of this phase: new attributes or questions, AI notices, limits, and status in the UI (Phase 14), deploying the quota Durable Object to production and production AI, discrimination-based question selection and early stopping, images (unless the owner decides otherwise in task 3), a dated exchange-rate table, the out-of-policy Access check, and the pre-public-release checklist.

- The bundle is imported on preview and production with bookmarks, `/api/diagnosis-content` matches it in all three locales, and complete quizzes in all three locales work on both environments.
- `npm run check` and `npm run test:e2e` pass after any change, AI is disabled in every environment, and the account stays on Workers Free.
