# Prompt 16 — Cost and season coverage

Production has 30 published destinations (`content/initial-v7.json`, which adds French translations to `initial-v6.json` in Phase 17). Only 8 have an indicative cost estimate and 18 have best months, so for most destinations the budget comparison shows `unknown` or `incomparable` and the season note shows `unknown` ([DIAGNOSTIC_ALGORITHM.md](../docs/en/DIAGNOSTIC_ALGORITHM.md) §5–§6). Three of the eight estimates exist in `JPY` only (Sydney, Queenstown, Cairns), so `USD` and `EUR` budgets cannot be compared with them. Most gaps are not unexplored: Phases 8, 9, and 13 checked sources and left items empty because no source met the owner's rules ("Phase 8 verification log" owner decisions, "Phase 13 verification log" "Checked, left empty"). This phase finds out what can be added within those rules, offers the owner rule options where the rules themselves block useful data, and adds only sourced values, so that budget and season notes work for more destinations without guessing. The first response is investigation and a proposal only: no content, code, configuration, or database change, no import, and no deployment.

Do not run remote Cloudflare commands, deploy, import content, change quiz settings, push, commit, or add, remove, or update dependencies without the owner's explicit approval for that action. Dashboard and admin-console steps on deployed environments are the owner's; describe them, do not perform them. The account must stay on Workers Free: the only accepted charge is the owner's existing domain registration. AI stays disabled in every environment; enabling it on production follows [DEPLOYMENT.md](../docs/en/DEPLOYMENT.md) 7.3 and is a separate owner decision, not part of this phase.

In the first week of December 2026, remind the owner of the dated Workers Logs and Billing check ([OPERATIONS.md](../docs/en/OPERATIONS.md) section 3 "Dated"), whether or not this phase is still open.

## Tasks
1. **Gap inventory (local, no change).** For each of the 30 destinations, list what it has (cost estimates by currency, best months, best-season text in each locale) and, for each gap, what earlier phases checked, which rule excluded it, and the date checked. Count how often a budget in `JPY`, `USD`, or `EUR` would be `unknown` or `incomparable` today.
2. **Re-check within the current rules (time-boxed).** For each gap, look for sources published or updated since the earlier check (for example a 2025 visitor survey released in 2026), and for best months on the official tourism pages that earlier phases did not use. Record every source read, with its date and the reason it qualifies or not. Stop at the time box agreed with the owner; do not lower the bar to fill a gap.
3. **Rule options (owner review).** Where the rules block data that would be useful, describe options with what each would add, its risk of misleading users, and the wording it would need, for example:
   - `USD` and `EUR` estimates for sources in other currencies (Sydney and Cairns in `AUD`, Queenstown in `NZD`), converted with a cited official annual average rate, as `JPY` is today;
   - other source types (for example a city tourism board's visitor survey) or an older survey year, with the year stated in the basis;
   - leaving the rules unchanged.
   Recommend one option per rule, including "no change". Do not apply any option before the owner decides.
4. **Proposal (owner review).** Per destination, the values to add under the approved rules: currency, period, scope, min, max, source name and URL, date checked, and the basis text curated in `ja` (the polite style of the UI), `en`, `es`, and `fr`; best months with the quoted source wording; best-season text where the source names a season without months. Never present a value as a live price, and never derive a value by dividing totals or per-trip figures.
5. **Bundle (after approval of task 4).** Create `content/initial-v8.json`: `initial-v7.json` plus the approved values only, with nothing else changed (check it by comparing the parsed files without the new fields). Extend `test/node/content-bundle.test.ts` if a new rule needs a check. Provide a rendered review copy in all four locales with every source linked before the commit. `npm run check` must pass.
6. **Import and checks (owner steps, each approved).** Amended 2026-11-01 because the preview environment was removed (ADR-033): a local rehearsal replaces preview, then production.
   - Local rehearsal (Claude, no remote command): reset the local database with `npm run db:reset:local`, import `initial-v7.json` and then `initial-v8.json` with the update mode on the local admin Import page (`npm run dev:admin`), and check that the "Changes" list only the new cost estimates.
   - Production (owner): import `initial-v8.json` with the update mode in the production admin console and check the "Changes" before importing ([OPERATIONS.md](../docs/en/OPERATIONS.md) section 8). No bookmark is needed: Time Travel restores by timestamp within 7 days, and the previous bundle can be re-imported (OPERATIONS.md sections 4.3 and 5, owner decision 2026-11-01).
   - Checks, locally and on production: `/api/diagnosis-content` matches the bundle in `ja`, `en`, `es`, and `fr`; complete quizzes in the built-in browser, covering all four locales, with budgets in `JPY`, `USD`, and `EUR` and travel months, checking the cost, budget, and season notes. On production, also run `node scripts/check-deployment.mjs <account subdomain> production`.
   - No code deployment is expected; if code changes, follow [DEPLOYMENT.md](../docs/en/DEPLOYMENT.md) section 5 and record the versions. Record the date and results in the "Phase 16 verification log" in `docs/working/DECISIONS.md`.
7. **Documentation.** Record the owner's rule decisions (ADR-008 or a new ADR), the new bundle in ADR-028 "Content files", the coverage before and after, and the root README status with its Japanese twin; update any stable doc whose rules change, with its Japanese twin.

Deferred, not part of this phase: new destinations, attributes, or questions; changes to attribute scores or option effects; the number of questions; enabling AI on production; images; a dated exchange-rate table beyond what an approved rule needs; the out-of-policy Access check; removing the overrides (ADR-030); and the pre-public-release checklist.

## Acceptance
- The gap inventory and the re-check are recorded, and the owner decided on each rule option before any value was added.
- Every new cost estimate, best-month entry, and best-season text has a cited source that meets the approved rules; items without one stay empty.
- `content/initial-v8.json` differs from `initial-v7.json` only by the approved values, and the owner approved the rendered review copy in all four locales.
- The bundle is imported in the local rehearsal and on production, `/api/diagnosis-content` matches it in all four locales, and complete quizzes with `JPY`, `USD`, and `EUR` budgets pass on both.
- `npm run check` (and `npm run test:e2e` if code changed) pass, AI is disabled in every environment, and the account stays on Workers Free.
